# Word Buster 仕様書

## 1. ゲーム概要

* **タイトル**: Word Buster（ワードバスター）
* **ジャンル**: 横スクロール・ガンアクション（ロックマン風）＋ 英語ミッションクリア型
* **コンセプト**: キャラクターの動作・画面上の物体・ナビゲーターからの指示を英語音声とスペル表示で結びつけ、英語を暗記するのではなく「状況を理解して操作につなげる」体験を通じて子どもの英語学習を支援する。
* **動作環境**: PCのWebブラウザ（Chrome等をメイン想定）
* **技術スタック**: HTML / CSS / Vanilla JavaScript（Canvas 2D描画）
* **音声エンジン**: ブラウザ標準 Web Speech API（`window.speechSynthesis`）

## 2. 対象ユーザー・英語学習方針

### 2.1 対象レベルと段階的な発展
* **対象ユーザー**: 6歳（簡単な日常英語が理解できるレベル）〜小学校の英語学習レベルを基本とする。
* **段階的学習**: 初期段階では短い単語や基本的な指示から始め、慣れやステージ進行に応じてオブジェクトと組み合わせた短い英文へ段階的に発展させる。
  * 初期例: `"Jump!"` / `"Shoot!"` / `"Look out!"`
  * 発展例: `"Jump over the box!"` / `"Get 3 coins!"` / `"Shoot the red slime!"`

### 2.2 英語音声と画面表示（日本語訳の扱い）
* **基本方針**: 通常時は英語音声＋英語表記のみとする（デフォルトは英語のみ表示）。
* **日本語訳の一時表示**:
  * `H` キー、または画面上のヒントボタンを押すと、日本語訳を一時表示する。
  * 日本語訳は一定時間経過すると自動的に消え、英語のみの表示に戻る。
  * 日本語訳の表示中もゲーム操作は継続できる。

| 要素 | 表示・動作例 |
| :--- | :--- |
| **英語音声** | `"Jump!"` |
| **画面表示** | `JUMP` |
| **日本語訳（補助）** | `H` キーまたはヒントボタン押下時のみ一時表示（例:「ジャンプ！」） |

### 2.3 ナビゲーター（案内役：Buddy）
* **名称・位置づけ**:
  * 固有名称は **Buddy（バディ）** とする。プレイヤーやゲーム内の会話では「Buddy」と呼ぶ。
  * 親しみやすく、子どもが名前を覚えやすい、主人公をサポートする相棒という位置づけの小型ロボット型キャラクター。
  * 英語の指示、ヒント、応援、成功・失敗時のメッセージを担当する（例: `"Jump!"`, `"Look out!"`, `"Get the key!"`）。
* **性格・コミュニケーション方針**:
  * 明るく元気で、主人公を応援する相棒タイプ。
  * 英語学習への意欲を高めるため、成功体験を重視したコミュニケーションにする。
  * **ミッション成功時**: 積極的に褒める（例: `"Great!"`, `"Awesome!"`, `"Well done!"`）。
  * **ミッション失敗時**: 否定的な表現を避け、前向きに励ます（例: `"Try again!"`, `"You can do it!"`）。
* **外見・カラーリング**:
  * メカニカルな小型ドローン型ロボット。プロペラまたは小型ジェットによって空中を飛行する。
  * カラーリングは **ホワイトをベースにオレンジをアクセント** として使用し、明るく元気な性格に合った親しみやすいデザインとする。
  * 主人公の赤いスーツと視覚的に区別できる配色にする。
  * 発光部分はオレンジ系を基本とし、感情表現に応じて色や明るさを変化させてもよい。
* **ステージ内での挙動・表示位置**:
  * ステージ中、主人公の近くを常時飛行し、主人公の移動・ジャンプ・攻撃に合わせて滑らかに追従する。
  * 基本飛行位置は **主人公の斜め後ろ・少し上方** とし、主人公との距離を一定に保ちながら追従する。
  * 主人公の向きが変わった場合も自然に位置を切り替え、主人公の攻撃やジャンプの視認性を妨げないようにする。
  * ミッション発生時には、HUD直下のミッションバナーにも登場する（HUD表示とステージ内のロボットは同一キャラクターとして扱う）。
* **アニメーション・感情表現（初期実装方針）**:
  * アニメーションはシンプルなものとし、開発負荷を抑えてゲーム本体と英語学習機能を優先する。
  * 通常時は空中で上下に軽く揺れる・ゆっくり浮遊するなど、自然なアニメーションを付ける。
  * 飛行時はプロペラやジェットの簡単なアニメーション（回転など）を表示する。
  * 目や発光部分の色・明るさの変化、およびミッション成功時に喜ぶ・失敗時に励ますといった動作によって感情を表現する。
  * 複雑な表情変化や状況に応じた自律行動は初期実装では行わない。
* **音声仕様**:
  * 自然な英語ネイティブ音声を基本とし、`en-US`（アメリカ英語）を優先する。
  * 子どもが聞き取りやすい明瞭な発音と、自然なイントネーションを重視する。
  * 過度な電子音やロボット風の音声加工は行わない。
  * 明るく元気な性格は、声のトーンやイントネーションで表現する。

### 2.4 英語学習とアクションの連携フロー
1. ナビゲーターが `"Jump!"` などの指示を英語音声で読み上げる。
2. 画面に `JUMP`（または英文ミッション）が表示される。
3. プレイヤーが対応する操作（ジャンプ、射撃、アイテム取得など）を行う。
4. 障害物の回避やゲート開放など、ゲーム内の結果につながる。
5. 画面上の物体やキャラクターの動作についても、英語音声とスペル表示を連動させる。

## 3. 画面構成・UI仕様

### 3.1 上部HUD（固定表示）
画面最上部にドット絵風のフレームを配置し、左から以下の要素を表示する。

1. **ライフ**: ハートアイコン × 3（ダメージまたはミッション失敗で減少・全ステージ共通仕様）
2. **残機**: キャラクター顔アイコン × `∞`（ライフ0時はチェックポイントまたはステージ開始地点からライフ全快でリトライ）
3. **コイン**: コインアイコン × 取得数
4. **スコア**: `Current`（現在のスコア） / `High`（`localStorage` に保存されるハイスコア）
5. **タイマー**: 時計アイコン ＋ ステージ経過時間（クリアタイム記録用）。ミッション発生中はミッションバナー側に個別の制限時間カウントダウンを表示する。
6. **設定ボタン**: 歯車アイコン（クリックでポーズ＆設定モーダルを開く）

### 3.2 設定モーダル
* **Voice Speed**: 英語音声の読み上げ速度（Slow / Normal）
* **Voice ON/OFF**: 音声読み上げの切り替え
* **Japanese Hint（検討中）**: 補助的な日本語訳表示のON/OFF
* **Resume / Restart**: ゲーム再開・ステージやり直し

### 3.3 英語学習UI
* **フローティングテキスト**: アクション切り替え時やオブジェクトに作用した際、キャラクターや対象の頭上に英語のスペルをポップアップ表示し、数秒後にフェードアウトさせる（例: `JUMP!`, `COIN`, `SLIME`）。
* **ミッションバナー（ナビゲーター表示）**: エリアごとの英語指示が発生した際、HUD直下にナビゲーター（Buddy）のアイコンとともに大きく指示文を表示する。
  * 聞き直し用のスピーカーアイコンを配置する。
  * 日本語訳確認用のヒントボタンを配置する。
  * 日本語訳は英語表示を隠さず、補助情報として併記する。

## 4. プレイヤーキャラクター・操作・発話ルール

### 4.1 キャラクター選択
* 人間の少年・少女を基本とし、**男の子・女の子を選択可能** にする。
* 解放要素によって見た目や性能が異なるキャラクターを追加・選択できる構想とする。

### 4.2 キーボード操作とアクション（ロックマン方式）
基本操作（左右移動・ジャンプ・ロックバスター方式の射撃）に加え、チャージショットを搭載する。

| アクション | キー割り当て | 挙動 | 発話・スペル表示（切替時） |
| :--- | :--- | :--- | :--- |
| **左右移動** | `←` `→`（補助: `A` `D`） | 左右に走る・向きを変える | `Run!` / `Walk!` |
| **ジャンプ** | `Space`（補助: `↑` / `W`） | ジャンプ（押し時間で高さ調整） | `Jump!` |
| **通常ショット** | `Z`（短押し） | アームキャノンから通常弾を発射（画面内最大3発） | `Shoot!` |
| **チャージショット** | `Z`（長押し→離す） | エネルギーを溜めて大型貫通弾を発射 | 溜め開始: `Charge!` / 発射: `Big shot!` |
| **指示の聞き直し** | `R` | 現在の英語ミッション音声を再再生 | （ミッション文を再生） |
| **日本語訳ヒント** | `H` | 日本語訳を一定時間一時表示（表示中も操作継続可） | - |
| **ポーズ** | `Esc` または `P` | ゲームを一時停止・設定表示 | - |

### 4.3 音声読み上げ（Web Speech API）の制御ルール
* **音声エンジン・優先音声**: Web Speech API の英語音声を利用し、利用可能な音声の中から `en-US`（英語ネイティブ音声）を優先選択する。
* **音声速度**: 設定画面で `Slow` / `Normal` を切り替えられるようにする。
* **発話トリガー**: アクションが切り替わった瞬間のみ発話する（例: 停止→移動、地上→ジャンプ）。連続入力による音声の渋滞を防ぐ。
* **優先度制御**:
  1. ナビゲーターのミッション指示・成功／失敗ボイス（最優先・割り込み再生。**読み上げ中は他の全音声をミュート**）
  2. オブジェクト作用時の単語（コイン取得、敵撃破など。ミッション読み上げ中は抑制）
  3. プレイヤーのアクションボイス（ミッション読み上げ中は抑制）

## 5. 登場オブジェクト・敵キャラクター仕様

### 5.1 ギミック・オブジェクト

| 名称 | 英語表示 | 役割・挙動 |

| **鍵** | `Key` | ミッション対象・扉の開放用アイテム。 |

### 5.2 敵キャラクター
ロボット・機械系、動物・モンスター系など複数種類を用意し、敵ごとに異なる行動パターンを設定する。

| 敵の系統・種類 | 具体例（英語表示） | 行動パターン・特徴 | 倒し方（案） |
| :--- | :--- | :--- | :--- |

## 6. ステージ進行・英語ミッション仕様

### 6.1 ステージ構成・進行・再挑戦
* **ワールド・ステージ数**:
  * 12つの世界を用意し、各世界に4ステージ（通常3ステージ＋ボス1ステージ）を配置する（現在 **合計48ステージ**）。
  * 将来的にさらに世界やステージを追加できる構造にする。
* **プレイ時間目安**: 1ステージあたり 3〜5分。
* **ゲーム進行形式**: 通常プレイ（移動・戦闘・コイン収集）とミッション（ゲート開放やナビゲーターの指示達成）を組み合わせる。
* **ステージ解放ルール**:
  * ステージは決められた順番で進行し、ステージをクリアすると次のステージが解放される（世界をまたいでも同じルールを適用）。
  * 各世界の4番目のステージを **ボスステージ** とし、ボスを撃破するとその世界をクリアした扱いとする。
  * ボス戦でも英語ミッションを導入し、英語の指示に従って攻撃・回避する。
* **再挑戦・記録**:
  * 一度解放されたステージは、いつでも自由に再挑戦できる。
  * クリア済みステージのスコアやハイスコアは保存する。

#### ステージ解放イメージ
1. **Forest World**: `Forest 1` → `Forest 2` → `Forest 3` → `Forest 4`（ボス：Forest Guardian）
2. **Desert World**: `Desert 1` → `Desert 2` → `Desert 3` → `Desert 4`（ボス：Rock Golem）
3. **Snow World**: `Snow 1` → `Snow 2` → `Snow 3` → `Snow 4`（ボス：Ice Machine）
4. **Robot World**: `Robot 1` → `Robot 2` → `Robot 3` → `Robot 4`（ボス：Mega Robot）
5. **Ocean World**: `Ocean 1` → `Ocean 2` → `Ocean 3` → `Ocean 4`（ボス：Giant Octopus）
6. **Volcano World**: `Volcano 1` → `Volcano 2` → `Volcano 3` → `Volcano 4`（ボス：Fire Dragon）
7. **Sky World**: `Sky 1` → `Sky 2` → `Sky 3` → `Sky 4`（ボス：Thunder Bird）
8. **Candy World**: `Candy 1` → `Candy 2` → `Candy 3` → `Candy 4`（ボス：Candy King）
9. **Space World**: `Space 1` → `Space 2` → `Space 3` → `Space 4`（ボス：Alien UFO）
10. **Castle World**: `Castle 1` → `Castle 2` → `Castle 3` → `Castle 4`（ボス：Dark Knight）
11. **Dino World**: `Dino 1` → `Dino 2` → `Dino 3` → `Dino 4`（ボス：T-Rex King）
12. **Ghost World**: `Ghost 1` → `Ghost 2` → `Ghost 3` → `Ghost 4`（ボス：Phantom Ghost）

※ 各ステージのクリアが次のステージの解放条件となる。

### 6.2 ボス構成・ボス戦仕様
* **ボス構成（全12体・個性別AI）**:
  * **Forest 4：Forest Guardian** — 巨大な森のモンスター。弾・ジャンプ・接近の基本バランス型。
  * **Desert 4：Rock Golem** — 岩石の大型モンスター。高速突進（`"Jump over the boss!"`）とジャンプ攻撃。
  * **Snow 4：Ice Machine** — 氷の大型ロボット。2連弾（`"Jump over the shots!"`）と突進。
  * **Robot 4：Mega Robot** — 大型戦闘ロボット。高低2方向弾と高速突進の総合戦。
  * **Ocean 4：Giant Octopus** — 巨大タコ型ボス。泡の拡散弾（`"Dodge the bubbles!"`）と大ジャンプ。
  * **Volcano 4：Fire Dragon** — 炎のドラゴン。空中ホバリングからの火の玉投下（`"Look up! Move left/right!"`）と急降下。
  * **Sky 4：Thunder Bird** — 雷の鳥。空中移動からの落雷弾・疾風突進・空中停止（`"Jump and shoot!"`）。
  * **Candy 4：Candy King** — お菓子の王様。キャンディ拡散弾（`"Dodge the candy!"`）・大ジャンプ・2連弾。
  * **Space 4：Alien UFO** — 宇宙UFO。空中投下・拡散ビーム・急降下。
  * **Castle 4：Dark Knight** — 闇の騎士。高速突進・2連斬撃波・ジャンプ。
  * **Dino 4：T-Rex King** — 恐竜王。大ジャンプ踏みつけ・猛突進・岩弾。
  * **Ghost 4：Phantom Ghost** — 幽霊の王。空中浮遊・拡散霊弾・上空投下の最終決戦。
* **ボス戦・英語ミッション**:
  * ボスの攻撃パターンや状況に応じて、Buddyが英語で指示を出す。
  * プレイヤーは指示の意味を理解し、適切な操作（攻撃・回避・移動など）を行う。
  * 通常ステージよりも状況判断を必要とする英文を使用する。
  * 英語の指示は音声と画面表示の両方で提示する（日本語訳は通常非表示とし、`H` キーまたはヒントボタンで確認できる仕様を適用）。

| 英語 | 日本語訳 |
| :--- | :--- |
| `Watch out!` | 気をつけて！ |
| `Jump over the attack!` | 攻撃を飛び越えて！ |
| `Shoot the weak point!` | 弱点を撃って！ |
| `Move left!` | 左に移動して！ |
| `Move right!` | 右に移動して！ |

* **攻撃パターン（初期実装）**:
  * ボスの攻撃パターンはシンプルなものにし、初期実装では以下の3種類を採用する。
    * 左右移動・接近
    * ジャンプ攻撃
    * 弾の発射
  * 攻撃パターンに応じてBuddyが英語で回避指示を出す。攻撃の種類を増やすよりも、英語の指示を理解して適切に操作する体験を優先する。
  * 複雑なフェーズ制やHPによる攻撃パターンの変化は初期実装では採用しない。
* **ダメージ・攻撃可能条件**:
  * ボスは常に攻撃可能な状態とし、通常ショット・チャージショットの両方でダメージを与えられる。
  * 弱点の露出や特定タイミングでのみ攻撃可能になる仕組みは採用しない。
  * Buddyの英語指示は、攻撃・回避・移動などの行動を促すものとし、プレイヤーが自由に攻撃しながら英語の指示に従って戦える設計とする。
* **耐久力・戦闘時間**:
  * ボスの耐久力は低めに設定し、**通常弾10〜15発程度** で撃破できるバランスを目安とする。
  * 想定戦闘時間は **30秒〜1分程度**。
  * 長期戦よりも、英語の指示を理解して攻撃・回避する楽しさと、子どもが短時間で達成感を得られる設計を優先する。

### 6.3 通常ステージのミッション例（バリエーション一覧）
ステージ途中のゲート前やエリア進入時にミッションが発生する。

1. **収集・基本アクション**: `"Get 3 coins!"` / `"Get the key!"` / `"Jump 3 times!"` / `"Shoot 5 times!"` / `"Use a big shot!"` / `"Jump and shoot 3 times!"`
2. **位置・方向・前置詞**: `"Jump on the left box!"` / `"Shoot the high bat!"` / `"Get the coin under the tree!"` / `"Look left, then look right!"`
3. **色・大きさ・形・数字・たし算の識別**: `"Shoot the red slime!"` / `"Shoot the big slime!"` / `"Get the blue star!"` / `"Shoot the green switch!"` / `"Shoot the triangle!"` / `"Shoot number 5!"` / `"What is 2 + 3?"`
4. **イラスト英単語・スペル**: `"Shoot the apple!"`（🍎/🍌/🍇等から絵を識別） / `"Shoot the moon!"` / `"Shoot the fish!"` / `"Shoot A, B, C!"` / `"Spell CAT!"` / `"Spell DOG!"` / `"Spell SUN!"`
5. **ルール・回避（キープ・禁止系）**: `"Don't move!"`（3秒静止） / `"Don't jump! Go to the gate!"`（ジャンプ禁止進行） / `"Stay on the tree!"`（3秒滞在） / `"Dodge the shots!"`（5秒回避）
6. **順番（2〜3ステップ）**: `"Jump on the box, then the tree!"` / `"Shoot red, then blue!"` / `"Shoot 1, 2, 3!"`
7. **ワールド固有ギミック**: `"Break the rock!"`（岩破壊） / `"Jump over the cactus!"`（砂漠のサボテン） / `"Break the ice!"`（雪原の氷） / `"Stop the laser!"`（ロボット工場のレーザー停止）

### 6.4 ライフ・制限時間・成功／失敗時の処理
* **ライフ・タイマー仕様**:
  * ライフは全ステージ共通で3（ダメージまたはミッション失敗で減少）。
  * ステージ全体は経過時間（クリアタイム記録）を計測し、**ミッション発生中のみ個別の制限時間カウントダウン**を行う。
* **成功時**:
  * `"Great!"` `"Open!"` などの褒め言葉を発話・フローティング表示。
  * ゲートが開き、ボーナススコアを加算して次のエリアへ進める。
* **失敗時（ライフ減少条件）**:
  * 敵キャラクターや敵弾に接触した時（被弾後は一定時間の無敵点滅あり）。
  * ミッションの制限時間が切れた時、または指示と異なる対象を攻撃した時。
  * 失敗時は `"Try again!"` などを発話・表示し、ライフを1つ減少させて再挑戦となる。
* **ライフ0時**:
  * 残機は `∞` のためゲームオーバーにはせず、ライフを3に回復して直前のエリア開始位置からリトライする。

## 8. グラフィック・サウンド方針

* **グラフィック**: プロトタイプ段階では外部画像ファイルを使用せず、JavaScript内のピクセル配列データからCanvas上へドット絵風スプライトを動的生成する。
  * 背景: 青空、雲、遠景の木々（パララックススクロール対応）
  * 地形: 草の生えた土ブロック
  * 主人公: 男の子／女の子（赤いスーツ・アームキャノン等）
* **効果音（SE）・BGM**:
  * Web Audio API を用いて、レトロゲーム風のショット音・チャージ音・ジャンプ音・コイン取得音・ゲート開放音などをコードで合成する。
  * 初回実装では英語音声の聞き取りやすさを優先し、**SE＋英語音声のみ**とする（BGMは後続フェーズで追加予定）。

## 10. フォルダ・ファイル構成設計

### 10.1 設計方針
* **ビルドツール不要（Vanilla HTML / CSS / JS）**: ブラウザ標準の ES Modules（`<script type="module">`）でモジュール分割し、外部ライブラリやバンドラなしで動作させる。
  * ※ ES Modules の制約上、ローカル実行時は簡易HTTPサーバー（例: `python3 -m http.server`）経由で開く前提とする。
* **責務分離**: ゲームループ・入力・音声などの「基盤（`core`）」、描画用の「スプライト・背景（`render`）」、キャラクターやギミックの「エンティティ（`entities`）」、ミッションや当たり判定の「システム（`systems`）」、ステージ定義の「データ（`data`）」に分離する。
* **Phase 2 以降の拡張性**: ワールド・ステージは `js/data/stages/` 配下にワールド単位でファイルを追加できる構造とし、将来の解放ショップやBGMも `js/ui/` や `js/core/` へ無理なく追加できるようにする。
